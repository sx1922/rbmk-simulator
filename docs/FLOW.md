## 1 · 问题陈述

当前代码中，App.startGame() 进入无限 requestAnimationFrame 循环，永不退出。无结算、无评分、无存档、无返回菜单路径。

本文档定义从"按下开始"到"回到菜单"的完整生命周期，使所有模块（场景引擎、评分、存档、结算 UI）有明确的接入点。

---

## 2 · 状态机

```
┌──────────────────────────────────────────────────────────┐
│                                                          │
│   ┌──────┐    ┌─────────┐    ┌────────┐    ┌────────┐   │
│   │ MENU │───→│ PLAYING │───→│ ENDING │───→│DEBRIEF │   │
│   └──────┘    └─────────┘    └────────┘    └────┬───┘   │
│      ↑                                          │       │
│      └──────────────────────────────────────────┘       │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

| 状态 | 含义 | 活跃模块 |
|------|------|----------|
| MENU | 主菜单（班次选择屏） | menu.js |
| PLAYING | 游戏进行中 | simulation.js, scenario.js, props.js, UI |
| ENDING | 终局触发，过渡动画（1-3 秒） | 过渡渲染 |
| DEBRIEF | 结算画面 | scoring.js, save.js, debrief UI |

### 状态转换规则

| 转换 | 触发者 | 条件 |
|------|--------|------|
| MENU → PLAYING | 玩家 | 主菜单选中模式 + ⏎ |
| PLAYING → ENDING | 见 §3 | 终局条件命中 |
| ENDING → DEBRIEF | 系统 | 过渡动画播完（自动） |
| DEBRIEF → MENU | 玩家 | ⏎ 或 Esc |

---

## 3 · 终局触发源

PLAYING → ENDING 的触发源共四类，按优先级排列：

| 优先级 | 触发源 | 条件 | 终局类型标记 |
|--------|--------|------|-------------|
| 1 | 物理引擎 | 堆芯熔毁 / 功率超量程 / 不可恢复事故 | MELTDOWN |
| 2 | 场景引擎 | 事件列表走完 / 终局条件命中 | SCENARIO_END |
| 3 | 玩家主动 | 按下"结束值班"键（F12）或菜单内"退班" | VOLUNTARY |
| 4 | 挑战模式专用 | 时间耗尽 / 目标达成 | CHALLENGE_END |

### 3.1 物理引擎触发（MELTDOWN）

当 simulation.js 检测到以下任一条件：
- 燃料温度 > 2800°C（熔毁阈值）
- 热功率 > 32000 MW（超量程 ×10）
- 空泡份额 > 100%（完全汽化）

→ 调用 App.endGame('MELTDOWN', { cause, timestamp, finalState })

不可覆盖。一旦触发，不接受任何"撤销"。

### 3.2 场景引擎触发（SCENARIO_END）

scenario.js 的事件列表包含终局事件（type: 'endgame'）。当事件被消费：

```json
{
  "type": "endgame",
  "endType": "EXPLOSION",
  "delay": 3000,
  "epilogue": "epilogue_04"
}
```

→ 调用 App.endGame('SCENARIO_END', { endType, epilogue })

### 3.3 玩家主动（VOLUNTARY）

| 模式 | 行为 |
|------|------|
| 自由操作 | F12 或 Esc 呼出暂停菜单 → "结束值班" → 确认 → 触发 |
| 历史重演 | 同上，但确认文案不同："中断试验？进度将记录。" |
| 挑战模式 | 同上，但视为放弃，评分标记 ABANDONED |

→ 调用 App.endGame('VOLUNTARY', { elapsed, mode })

### 3.4 挑战模式专用（CHALLENGE_END）

| 条件 | 终局类型 |
|------|----------|
| 倒计时归零且目标未达成 | TIMEOUT |
| 目标达成（如"稳定运行 60 秒"） | OBJECTIVE_COMPLETE |

→ 调用 App.endGame('CHALLENGE_END', { result, score })

## 4 · 各模式的终局矩阵

| 模式 | 可能的终局类型 | 结算内容 |
|------|---------------|----------|
| 自由操作 (СМЕНА) | MELTDOWN / VOLUNTARY | 运行时长、最终状态快照、是否炸堆 |
| 历史重演 (ХРОНИКА) | MELTDOWN / SCENARIO_END / VOLUNTARY | 历史匹配度、关键决策记录、尾声文本 |
| 挑战模式 (ВЫЗОВ) | MELTDOWN / CHALLENGE_END / VOLUNTARY | 得分、排名（本地）、是否达标 |

---

## 5 · ENDING 过渡（PLAYING → DEBRIEF 之间）

不是硬切。根据终局类型，过渡不同：

| 终局类型 | 过渡表现 | 时长 |
|----------|----------|------|
| MELTDOWN | 屏幕白化 → 结构撕裂声 → 红光 → 渐暗 | 3s |
| SCENARIO_END（爆炸） | 同上 | 3s |
| SCENARIO_END（安全） | 屏幕正常渐暗，荧光灯熄灭声 | 2s |
| VOLUNTARY | 荧光灯熄灭，CRT 缩成亮点消失 | 1.5s |
| CHALLENGE_END | 计时器停止，数字定格，渐暗 | 1.5s |
| TIMEOUT | 计时器闪红，蜂鸣，渐暗 | 2s |

过渡期间不接受任何输入。

## 6 · DEBRIEF 结算画面

### 6.1 布局

复用主菜单双栏逻辑。左栏 = 数据，右栏 = 评语/尾声。

```
┌──────────────────────────────────────────────────────────┐
│  СМЕНА ЗАВЕРШЕНА / 值班结束                              │
├────────────────────────────┬─────────────────────────────┤
│                            │                             │
│  运行时长    04:23:17      │  "你做了正确的事。          │
│  终局类型    安全停堆       │   没有人感谢你。"           │
│  最终功率    0 MW          │                             │
│  ORM         22 根         │                             │
│  氙毒        正常          │                             │
│  操作次数    47            │                             │
│  关键决策    2             │                             │
│                            │                             │
├────────────────────────────┴─────────────────────────────┤
│  ⏎ 返回菜单          历史匹配度: 95%                     │
└──────────────────────────────────────────────────────────┘
```

### 6.2 各模式的结算差异

| 模式 | 左栏数据 | 右栏内容 |
|------|---------|----------|
| 自由操作 | 时长、终局、最终功率、ORM、操作次数 | 一句话评语（根据是否炸堆） |
| 历史重演 | 时长、终局、关键决策列表、历史匹配度 | 尾声文本（多行，逐行淡入） |
| 挑战模式 | 时长、得分、目标状态、操作次数 | 达标/未达标 + 本地排名 |

### 6.3 历史重演的"关键决策列表"

记录玩家在场景中的分支选择：

```
00:32  停堆 / 继续          → 继续
01:03  关闭 САОР           → 服从
01:23  按下 АЗ-5           → 执行
```

如果玩家发现过规程线索，额外显示：

```
[!] 你看到了第 47 页。但你还是按了。
```

### 6.4 操作

| 按键 | 行为 |
|------|------|
| ⏎ / Esc | 返回主菜单（DEBRIEF → MENU） |

无其他操作。结算画面是终点，不是交互界面。

## 7 · 模块接入接口

### 7.1 App.endGame()

```
App.endGame(type, payload)
// type: 'MELTDOWN' | 'SCENARIO_END' | 'VOLUNTARY' | 'CHALLENGE_END'
// payload: { ... } 各类型不同，见 §3
```

调用后：
1. 停止 simulation tick
2. 停止 scenario engine
3. 播放过渡动画（§5）
4. 过渡完成后 → 调用 scoring.js 计算
5. 调用 save.js 写入
6. 渲染 DEBRIEF 画面（§6）

### 7.2 scoring.js 接口

```
Scoring.evaluate({
  mode,           // 'free' | 'story' | 'challenge'
  endType,        // 终局类型
  duration,       // 运行时长（ms）
  finalState,     // simulation 最终快照
  decisions,      // 场景引擎记录的决策列表
  flags           // 全局 flag（如"发现过规程线索"）
}) → ScoreReport
```

### 7.3 save.js 接口

```
Save.recordShiftEnd({
  timestamp,
  mode,
  endType,
  scoreReport,
  decisions
})
```

键名统一为 `'rbmk_journal'`。menu.js 中的 `'rbmk_save'` 废弃。

## 9 · 暂停菜单（Esc 浮层）

游戏内按 Esc 弹出暂停浮层（半透明遮罩 + 中央卡片）：

```
┌─────────────────────────────┐
│  ПАУЗА / 暂停               │
│                             │
│  ▸ 继续值班                 │
│    整定（设置）             │
│    结束值班                 │
│                             │
│  Esc 继续                   │
└─────────────────────────────┘
```

- "继续值班"：关闭浮层，恢复 tick
- "整定"：打开设置屏（复用 MENU-01 §5 的设置组件）
- "结束值班"：触发 VOLUNTARY 终局（§8）

暂停期间 simulation tick 冻结。场景引擎时钟冻结。

## 10 · 实现顺序

| 步 | 任务 | 依赖 |
|----|------|------|
| 0 | App 状态机 + endGame() 接口 | 无 |
| 1 | 暂停菜单（Esc 浮层）+ "结束值班" → VOLUNTARY | 步 0 |
| 2 | 物理引擎熔毁检测 → MELTDOWN | 步 0 |
| 3 | DEBRIEF 结算画面（最简版：终局类型 + 时长 + 返回按钮） | 步 0 |
| 4 | 接 scoring.js：endGame() 内调用 | 步 3 |
| 5 | 接 save.js：endGame() 内调用，统一键名 | 步 4 |
| 6 | 接场景引擎：startGame('story') 创建 ScenarioEngine | 步 0 |
| 7 | 场景引擎终局事件 → SCENARIO_END | 步 6 |
| 8 | DEBRIEF 完整版：决策列表、匹配度、尾声 | 步 7 |
| 9 | 挑战模式终局 | 步 0 |

步 0-3 完成后，游戏即可闭环（能开始、能结束、能看到结果、能回菜单）。
