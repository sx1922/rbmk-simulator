## 1 项目概述

### 1.1 一句话描述

操作一台有致命设计缺陷的 RBMK-1000 反应堆，在物理规律、经济压力、政治信任之间求生。

### 1.2 类型定义

| 维度 | 定义 |
|------|------|
| 类型 | 核电站控制室模拟 + 经营管理 |
| 视角 | 控制台面板（非俯视，非第一人称） |
| 核心循环 | 监控 → 操作 → 应对事件 → 维持平衡 → 推进时间 |
| 单局时长 | 无固定终局，直到灾难/行政终局 |
| 重玩性来源 | 随机事件 + 季节变化 + 不同决策路径 + 难度梯度 |

### 1.3 核心体验关键词

| 关键词 | 说明 |
|--------|------|
| 紧张感 | 任何操作都可能触发连锁反应，没有"安全"操作 |
| 理解感 | 玩家逐渐理解物理规律，从"按按钮"到"懂原理" |
| 无力感 | 设计缺陷是结构性的，你无法修复它，只能管理它 |
| 历史感 | 你在走 1986.4.26 那条路，每一步都有据可查 |

### 1.4 游戏定位

第一人称核电站操作模拟。玩家扮演切尔诺贝利核电站第四机组的站长，在 1986 年 4 月的背景下，负责反应堆的日常运行、安全管理，并最终面临是否进行安全试验的选择。

### 1.5 核心体验

- **真实的物理模拟**：中子动力学、氙毒、空泡系数、温度反馈、AZ-5 瞬态
- **运营压力**：发电指标、设备维护、人员管理、上级信任
- **决策后果**：每一个操作都有物理和经济上的连锁反应
- **历史再现**：可完整经历切尔诺贝利事故的决策链

### 1.6 红线

- 不美化核事故
- 不简化操作过程
- 不回避辐射后果

## 2 核心设计理念

1. **物理先行**：所有游戏机制建立在物理模拟之上
2. **操作即后果**：无"正确"操作，只有权衡
3. **信息不完美**：仪表有误差、延迟、故障
4. **压力渐进**：难度不是通过数值堆叠，而是通过多种压力源叠加

## 3 背景与世界观

1986 年 4 月，切尔诺贝利核电站，列宁核电站第四机组。RBMK-1000 型反应堆，正空泡系数，石墨慢化，沸水冷却。

## 4 核心循环

```
玩家操作 → 修改 STATE → 物理步进 → 更新显示 → 等待下个操作
```

每 0.5 秒步进一次物理（对应游戏内约 15 分钟），玩家可随时介入。

## 5 反应堆物理模型

### 5.1 点堆中子动力学（6 组缓发中子）

- 功率范围：1e-6 ~ 2.0（归一化）
- 瞬发中子代时间 Λ = 1e-4 s
- 缓发中子份额 β = 0.006502（6 组）
- 数值方法：RK4 自适应步长

### 5.2 反应性合成

```
ρ_total = ρ_棒 + ρ_空泡 + ρ_燃料 + ρ_氙 + ρ_外部
```

各项系数：
- 空泡系数：α_void = +2.8e-4 Δρ/%void（RBMK 为正！）
- 多普勒系数：α_fuel = -2.4e-5 Δρ/°C
- 石墨温度系数：α_graphite = +1.2e-6 Δρ/°C

### 5.3 控制棒价值

采用余弦平方积分模型：
```
ρ_rod(x) = -W_total · (1 - cos(π · x)) / 2
```
其中 W_total = 0.10（总棒价值），x 为归一化棒位（0 = 全插，1 = 全提）。

### 5.4 棒端效应（正停堆效应）

石墨置换棒进入水区域时引入正反应性，峰值约 0.0010 Δρ，呈高斯分布：
```
ρ_tip(x) = TIP_PEAK · exp(-0.5 · (x / TIP_W)²)
```

### 5.5 AZ-5 紧急保护

三相插入：
1. 石墨端进入堆芯 → 可能的正反应性尖峰
2. 主吸收段进入
3. 全插到位

## 16 难度设计

### 16.1 核心原则

难度不是"敌人更强"。难度是"给你的更少"。

没有血条，没有敌人，没有倒计时读条。难度的本质是：你和反应堆之间，隔了多少层信息。

### 16.2 难度维度

不是一个滑块。是五个独立轴。

| 轴 | 低难度 | 高难度 |
|----|--------|--------|
| 信息透明度 | 异常参数高亮闪烁，故障源直接标注 | 所有仪表一视同仁，你自己判断哪个不对 |
| 时间裕度 | 从异常到不可逆，5 分钟以上 | 90 秒 |
| 规程辅助 | 手册自动翻到相关页，步骤逐条提示 | 手册在那，自己找，自己读，没人等你 |
| 容错 | 错误操作有缓冲期，可以撤回 | 一步错，直接进事故工况 |
| 指令明确度 | 值班长说"把功率降到 50%" | 值班长说"上面不满意，你看着办" |

### 16.3 难度等级

难度不叫"简单/普通/困难"。叫值班等级。叙事内嵌。

| 等级 | 名称 | 叙事含义 | 对应玩家 |
|------|------|----------|----------|
| 1 | 实习操纵员 | 师傅在旁边，什么都告诉你 | 第一次玩 |
| 2 | 值班操纵员 | 独立值班，规程在手，时间够用 | 通关一次后 |
| 3 | 高级操纵员 | 没有提示，时间紧，指令模糊 | 追求挑战 |
| 4 | 事故工况 | 一切都在坏，信息互相矛盾，没有正确答案 | 自虐 |

不设"自定义难度"。五个轴绑定在等级里，不拆开给玩家调。原因：这游戏的核心体验是"在信息不足时做决定"。如果玩家把信息透明度拉满，游戏就不存在了。

### 16.4 各等级具体差异

**等级 1：实习操纵员**
- 异常仪表黄色闪烁 + 文字标注"注意：一回路温度偏高"
- 手册自动打开到对应章节，当前步骤加粗
- 值班长指令具体到操作："将第 12 组控制棒下插 30 厘米"
- 错误操作后 10 秒内可撤回（棒可以拉回来，阀门可以关回去）
- 从异常到不可逆：8 分钟
- 结算时额外显示"你本应该做什么"

**等级 2：值班操纵员**
- 异常仪表仅闪烁，无文字标注
- 手册不自动翻页，但目录有标记
- 值班长指令是目标："把一回路温度压回 280"
- 错误操作有 3 秒缓冲，之后锁定
- 从异常到不可逆：4 分钟
- 结算时显示标准评价

**等级 3：高级操纵员**
- 无闪烁。仪表就是仪表。你自己看。
- 手册无任何辅助。
- 值班长指令模糊："上面问你怎么回事，你给个说法"
- 无缓冲。操作即生效。
- 从异常到不可逆：2 分钟
- 结算时只显示结果，不解释

**等级 4：事故工况**
- 部分仪表给错误读数（传感器故障）
- 手册可能缺页（被撕了、被咖啡泡了）
- 值班长可能给错误指令（他也不知道发生了什么）
- 无缓冲。且存在"操作本身加剧事故"的可能
- 从异常到不可逆：60 秒
- 没有"正确答案"。结算时显示"你做了什么"和"发生了什么"，不评价对错

### 16.5 难度递进（跨场景）

不是"第一关简单第二关难"。是同一等级内，场景本身在变复杂。

| 阶段 | 特征 |
|------|------|
| 前期场景 | 单一故障。一个参数偏了。你调回来。完事。 |
| 中期场景 | 耦合故障。调了一个，另一个跟着动。你得想顺序。 |
| 后期场景 | 信息矛盾。两个仪表说的不一样。你得判断谁坏了。 |
| 终局场景 | 没有正确操作。你只能选"哪种死法"。 |

难度等级决定你获得多少帮助。场景进度决定问题本身有多复杂。两者独立。

一个等级 1 的玩家在后期场景里也会遇到信息矛盾——只是游戏会告诉他"这两个仪表矛盾了"。等级 3 的玩家在前期场景里也不会得到提示——只是问题本身简单，不需要提示也能过。

### 16.6 解锁规则

| 等级 | 解锁条件 |
|------|----------|
| 1 | 默认 |
| 2 | 以等级 1 完成全部场景 |
| 3 | 以等级 2 完成全部场景，且总评分 ≥ B |
| 4 | 以等级 3 完成全部场景 |

不跳级。原因：等级 3 和 4 要求玩家已经内化了规程。如果没经历过等级 1 和 2 的辅助阶段，玩家不是在"做困难决定"，是在"乱按"。

### 16.7 与其他系统的接口

| 系统 | 接口 |
|------|------|
| SCENARIO.md | 场景脚本中标注 min_difficulty 字段。低于此等级的玩家不会遇到该场景的某些分支。 |
| SCORING.md | 等级 4 的结算使用不同的评价模板（不评对错，只记录）。 |
| UI_INTERACTION.md | 等级 1-2 的 UI 有额外高亮层。等级 3-4 移除。 |
| AUDIO_IMPL.md | 等级 1 有语音提示（"注意，一回路温度超限"）。等级 3 起只有报警声，没有语音。 |

### 16.8 不做的事

| 不做 | 原因 |
|-----|------|
| 辅助模式/无障碍模式 | 信息透明度已经是最低难度轴。再低就没有游戏了。 |
| 一命通关 | 这游戏本来就是一命。没有 checkpoint。事故就是事故。 |
| 动态难度调节 | 不根据玩家表现偷偷调参数。难度是透明的、固定的。 |
| 简单模式跳过某些场景 | 所有等级玩同样的场景。差异只在辅助程度。 |

## 21 版本号系统

### 21.1 完整格式

```
v{major}.{minor}.{patch} · сб.{YYYY.MM.DD} · РЭ-{YY}/{NN}
```

示例：`v0.1.0 · сб.2026.07.30 · РЭ-86/12`

### 21.2 三层职责

| 层 | 格式 | 职责 |
|----|------|------|
| 语义版本 | v{major}.{minor}.{patch} | 技术层，管"改了什么" |
| 构建日期 | сб.{YYYY.MM.DD} | 时间层，管"什么时候" |
| 修订代号 | РЭ-{YY}/{NN} | 叙事层，管"游戏里的身份" |

### 21.3 语义版本规则

- **major**：大版本，游戏发生质变（正式发布、引擎重写）
- **minor**：中版本，新增可感知的功能模块
- **patch**：小版本，修 bug、调数值、改文案
- minor +1 → patch 归零；major +1 → minor 和 patch 均归零
- major = 0 表示开发阶段，major = 1 表示正式发布

### 21.4 修订代号规则

- 修 bug / 调参数（patch +1）：修订代号不变
- 新增功能模块（minor +1）：NN +1
- 新增机组场景（新 YY）：YY 更换，NN 重置为 01
- 重大重做（major +1）：全部重置

| 版本 | 代号 | 含义 |
|------|------|------|
| v0.1 | Первый щит | 第一面屏 |

## 各系统设计意图

| 系统 | 意图 |
|------|------|
| 中子动力学 | 让玩家感受反应堆对操作的响应延迟和非线性 |
| 热工水力 | 让空泡系数成为核心风险 |
| 氙毒 | 强制玩家规划功率变化，不能随意启停 |
| 汽轮机 | 让发电效率与反应堆功率解耦 |
| 经济/政治 | 制造"安全生产 vs 完成指标"的核心矛盾 |
| 人员 | 让玩家不能只关注反应堆，还要关心操作员状态 |
| 安全试验任务链 | 让历史事件以可交互的方式呈现 |
