## 1 项目概述

### 1.1 一句话描述

操作一台有致命设计缺陷的 RBMK-1000 反应堆，在物理规律、经济压力、政治信任之间求生。

### 1.2 类型定义

| 维度 | 定义 |
|------|------|
| 类型 | 核电站控制室模拟 + 经营管理 |
| 视角 | 控制台面板（非俯视，非第一人称） |
| 核心循环 | 监控 → 操作 → 应对事件 → 维持平衡 → 推进时间 |
| 单局时长 | 无固定终局，直到灾难/行政终局 |
| 重玩性来源 | 随机事件 + 季节变化 + 不同决策路径 + 难度梯度 |

### 1.3 核心体验关键词

| 关键词 | 说明 |
|--------|------|
| 紧张感 | 任何操作都可能触发连锁反应，没有"安全"操作 |
| 理解感 | 玩家逐渐理解物理规律，从"按按钮"到"懂原理" |
| 无力感 | 设计缺陷是结构性的，你无法修复它，只能管理它 |
| 历史感 | 你在走 1986.4.26 那条路，每一步都有据可查 |

### 1.4 游戏定位

第一人称核电站操作模拟。玩家扮演切尔诺贝利核电站第四机组的站长，在 1986 年 4 月的背景下，负责反应堆的日常运行、安全管理，并最终面临是否进行安全试验的选择。

### 1.5 核心体验

- **真实的物理模拟**：中子动力学、氙毒、空泡系数、温度反馈、AZ-5 瞬态
- **运营压力**：发电指标、设备维护、人员管理、上级信任
- **决策后果**：每一个操作都有物理和经济上的连锁反应
- **历史再现**：可完整经历切尔诺贝利事故的决策链

### 1.6 红线

- 不美化核事故
- 不简化操作过程
- 不回避辐射后果

## 2 核心设计理念

1. **物理先行**：所有游戏机制建立在物理模拟之上
2. **操作即后果**：无"正确"操作，只有权衡
3. **信息不完美**：仪表有误差、延迟、故障
4. **压力渐进**：难度不是通过数值堆叠，而是通过多种压力源叠加

## 3 背景与世界观

1986 年 4 月，切尔诺贝利核电站，列宁核电站第四机组。RBMK-1000 型反应堆，正空泡系数，石墨慢化，沸水冷却。

## 4 核心循环

```
玩家操作 → 修改 STATE → 物理步进 → 更新显示 → 等待下个操作
```

每 0.5 秒步进一次物理（对应游戏内约 15 分钟），玩家可随时介入。

## 5 反应堆物理模型

### 5.1 点堆中子动力学（6 组缓发中子）

- 功率范围：1e-6 ~ 2.0（归一化）
- 瞬发中子代时间 Λ = 1e-4 s
- 缓发中子份额 β = 0.006502（6 组）
- 数值方法：RK4 自适应步长

### 5.2 反应性合成

```
ρ_total = ρ_棒 + ρ_空泡 + ρ_燃料 + ρ_氙 + ρ_外部
```

各项系数：
- 空泡系数：α_void = +2.8e-4 Δρ/%void（RBMK 为正！）
- 多普勒系数：α_fuel = -2.4e-5 Δρ/°C
- 石墨温度系数：α_graphite = +1.2e-6 Δρ/°C

### 5.3 控制棒价值

采用余弦平方积分模型：
```
ρ_rod(x) = -W_total · (1 - cos(π · x)) / 2
```
其中 W_total = 0.10（总棒价值），x 为归一化棒位（0 = 全插，1 = 全提）。

### 5.4 棒端效应（正停堆效应）

石墨置换棒进入水区域时引入正反应性，峰值约 0.0010 Δρ，呈高斯分布：
```
ρ_tip(x) = TIP_PEAK · exp(-0.5 · (x / TIP_W)²)
```

### 5.5 AZ-5 紧急保护

三相插入：
1. 石墨端进入堆芯 → 可能的正反应性尖峰
2. 主吸收段进入
3. 全插到位

## 7 汽轮机与二回路

### 7.1 结构

两台 K-500-65/3000 型汽轮机，每台额定 500 MWe，转速 3000 rpm。
蒸汽来自两台分离器（Сепаратор-Пароперегреватель），压力 6.0 MPa。

- 额定电功率：500 MWe × 2
- 额定转速：3000 rpm
- 蒸汽压力：6.0 MPa
- 超速保护：3150 rpm 动作
- 蒸汽温度：284°C

### 7.2 冷凝系统

排汽在冷凝器内由循环水冷却，循环水取自冷却池/塔。
冷凝器真空度影响发电效率，真空恶化则机组出力下降。

| 故障 | 原因 | 后果 |
|------|------|------|
| 真空恶化 | 循环水温升高 / 空气漏入 | 出力下降 5-15% |
| 冷凝器泄漏 | 循环水污染凝结水 | 二回路水质恶化 |
| 末级叶片损伤 | 低频疲劳 / 水蚀 | 振动上升 → 跳机 |

### 7.3 给水系统

凝结水泵 → 低压加热器 → 除氧器 → 给水泵 → 高压加热器 → 分离器。

- 给水泵：电动 + 汽动各 2 台
- 除氧器：压力 0.6 MPa，温度 158°C
- 给水温度：额定 230°C

### 7.4 保护系统

| 保护 | 定值 | 动作 |
|------|------|------|
| 超速 | 3150 rpm | 紧急关主汽阀 |
| 真空低 | < 0.06 MPa | 降负荷 / 停机 |
| 振动大 | > 0.15 mm | 报警 / 停机 |
| 润滑油压低 | < 0.03 MPa | 停机 |

### 7.5 惰转试验

惰转试验（场景 2 核心）流程：快速关主汽阀 → 涡轮惰转 → 靠惯性维持泵转速 → 柴油发电机启动 → 恢复。试验窗口约 15 秒，柴油不启动则泵流量急剧下降 → 反应堆面临冷却不足。
详见 `SCENARIO_ISPYTANIE.md`。

## 8 经济系统

### 8.1 收入

| 来源 | 计算 | 频率 |
|------|------|------|
| 售电 | 功率(MW) × 时间(h) × 电价 | 连续 |
| 容量奖金 | 可用率 > 90% 时奖励 | 月度 |
| 调峰补贴 | 响应电网调度指令 | 事件触发 |

电价模型：
```
基础电价 = 0.02 ₽/kWh（固定，2 戈比/kWh，符合 1986 年苏联工业电价水平）
市场波动 = ±30%，周期约 7 天（正弦 + 噪声）
季节系数 = 冬季 1.2 / 夏季 1.1 / 春秋 1.0
紧急折扣 = 电网要求降功率时，电价 × 0.7
```
货币单位：卢布（рубль / ₽），一切结算以卢布计。1 卢布 = 100 戈比。

### 8.2 支出

| 项目 | 频率 | 说明 |
|------|------|------|
| 燃料采购 | 换料时 | 大头，一次性能 |
| 日常维护 | 月度 | 固定 + 设备老化附加 |
| 人员工资 | 月度 | 按编制 |
| 监管罚款 | 事件触发 | 安全违规、超标排放 |
| 大修费用 | 换料周期 | 停堆 = 零收入 + 高额支出 |
| 设备更换 | 事件触发 | 泵、阀门、仪表等 |
| 培训 | 手动 | 初期投入，长期回报 |
| 改造 | 法规触发 | 新法规合规改造 |

### 8.3 月度结算

每月结算一次：收支差额 → 累积利润/亏损。

- 发电指标完成率影响上级评价
- 利润率影响预算分配
- 连续 3 个月净亏损 → 警告
- 连续 6 个月净亏损 → 电站被接管，游戏结束

### 8.4 经济压力

无尽模式下经济压力随设备老化递增：维护需求增大 → 支出上升 → 利润收窄 → 被迫削减维护 → 设备进一步老化（恶性循环）。核心决策：当利润不够时，你削减哪个预算？
详见 `ENDLESS_MODE.md`。

## 9 政治信任系统

### 9.1 权力链

```
玩家（值班班长）→ 站长 → 上级主管部门 → 国家核安全监管机构
```

### 9.2 核心机制

信任值范围 0-100，初始 70。归零 → 撤职终局。

| 影响 | 幅度 |
|------|------|
| 月度自然衰减（按难度） | -3~-8 / 月 |
| 完成发电指标 | +5~+15 |
| 安全事件 / 违规被发现 | -10~-40 |
| 定期汇报 / 配合检查 | +2~+5 |
| 拒绝上级不合理指令 | -10~-20（但可能长期受益） |
| 领导视察评价好 | +10~+20 |
| 隐瞒问题被揭发 | -40~-60 |

### 9.3 压力来源

| 来源 | 要求 | 不满足的后果 |
|------|------|-------------|
| 站长 | 发电指标、可用率 | 警告 → 撤职 |
| 主管部门 | 利润、上缴 | 削减预算 → 恶性循环 |
| 监管机构 | 安全合规、报告 | 罚款 → 停堆整顿 → 吊销执照 |

### 9.4 政治事件

15 个政治事件（PL-001~015），涵盖视察、指标加压、信任危机、预算、媒体、换届、腐败、IAEA、抗议、改制、甩锅、亲信、政策突变、举报。每个事件有独立选项树，玩家决策影响信任值和后续概率。
详见 `EVENTS.md`、`EVENTS_POLITICAL_EXTENDED.md`。

## 10 人员与组织系统

### 10.1 编制

| 岗位 | 人数 | 职责 |
|------|------|------|
| 值班班长（玩家） | 1 | 决策 |
| 操纵员 | 2-3 | 执行操作，响应速度取决于技能 |
| 现场操作员 | 2-4 | 现场巡检、手动操作 |
| 维修班 | 3-5 | 设备维护、抢修 |
| 辐射防护 | 1-2 | 监测、去污 |

### 10.2 人员属性

每人有：

- **技能等级**（1-5）：影响操作速度、失误率
- **疲劳**（0-100）：连续工作上升，休息下降。高疲劳 → 失误率飙升
- **士气**（0-100）：影响主动性和报告意愿。低士气 → 隐瞒异常（HU-003）
- **辐射剂量**（累积）：超标 → 强制离岗

### 10.3 班次与疲劳

- 正常 8 小时班次，疲劳 +20
- 加班：可强制留人，疲劳 +40，士气 -10
- 休息：交班后疲劳自然恢复
- 人手不足时被迫加班 → 恶性循环

### 10.4 培训

- 花钱送人培训 → 技能 +1（需要时间，期间少一个人）
- 事故后强制培训 → 免费但士气下降

### 10.5 人事事件

| 事件 | 触发 | 后果 |
|------|------|------|
| 操作失误 HU-001 | 高疲劳 / 低技能 | 可能触发设备故障 |
| 巡检遗漏 HU-002 | 疲劳高 / 人手不足 | 设备故障跳过预警 |
| 隐瞒异常 HU-003 | 士气 < 20 | 玩家看不到早期事件 |
| 违规操作 HU-004 | 士气低 / 玩家指令 | 安全隐患 |
| 事故追责 | 严重事故后 | 玩家可能被撤职 |

详见 `ENDLESS_MODE.md`。

### 13.2 严重度

| 等级 | 含义 | 时间压力 |
|------|------|----------|
| 1 | 提示 | 无 |

| 3 | 警告 | 秒到分钟 |
| 4 | 紧急 | 秒级 |
| 5 | 灾难 | 即时 |

### 13.3 频率模型

```
实际频率 = 基础频率 × 设备老化系数 × 维护质量倒数 × 人员状态系数
```

- 前 3 个月不出现 severity 4+（保护机制）
- 事件有 escalation 链：处理失败 → 升级下一级事件，严重度 +1
- 5 级事件必有至少 2 步前置警告

### 13.4 事件结构

每个事件定义：id、category、severity、触发条件、可选选项（每选项含 label、requirement、delay、success_rate、effects）、escalation 目标。

### 13.5 与模式的关系

- **历史模式**：不使用此系统，事件由场景引擎按剧本固定触发，详见 `SCEN_ENGINE.md`、`SCENARIO_ISPYTANIE.md`
- **无尽模式**：完全使用，生成器按频率表 + 修正系数随机抽取

详见 `EVENTS.md`、`EVENTS_POLITICAL_EXTENDED.md`。

## 14 安全试验任务链

### 14.1 结构

六幕剧本 «Испытание»（试验）构成完整一天（1986.4.25-26）：

```
第一幕 «Смена»        白班·交班          无分支·教学
第二幕 «Яма»          氙坑               ★ 分支点
  ├─ 继续线 ──→ 第三幕 «Тяга»           拉功率
  │              第四幕 «Подготовка»      试验准备
  │              第五幕 «АЗ-5»            紧急停堆
  │              第六幕 «После»           之后
  │
  └─ 停堆线 ──→ 第二幕B «Ожидание»      等待
                 第三幕B «Заново»         重来
                 尾声B «Тихий»            安静的人（隐藏结局）
```

| 幕 | 时间 | 内容 | 类型 | 压力 |
|----|------|------|------|------|
| 1 «Смена» | 08:00-14:00 | 交班、巡检、降功率至 1600 MW、泵振动、试验推迟 | 教学 | 零 |
| 2 «Яма» | 23:10-00:30 | 氙坑，分支点：停堆线 or 继续线 | 选择 | 低 |
| 3 «Тяга» | 00:30-01:00 | 拉功率，最低 200 MW 关口 | 操作 | 中 |

### 14.2 玩家角色

- 第一幕：白班操纵员（Топтунов 的前任，虚构人物），负责教学
- 第二幕起：夜班操纵员列昂尼德·托普图诺夫，25 岁，第一次独立值班

### 14.3 分支与结局

- 分支点设在第二幕（氙坑）：玩家在"安全"和"服从"之间做选择
- 分支由玩家动作检测触发（AZ 下插 / 提棒 / САОР 切除 / 汽轮机解列），见 `SCEN_ENGINE.md`
- 结局不是动画，是文字：黑屏白字
- 隐藏结局 «Тихий»：走停堆线后达成特殊条件解锁

### 14.4 场景设计哲学

- 场景不是"关卡"，是"值班"。没有开始按钮——你坐下来，面板亮了，你已经在值班了。
- 没有"任务目标"弹窗——你的任务在规程手册里，在电话里，在值班主任的嘴里。
- 没有"重玩"按钮——有，但它叫"重新值班"。
- 不做分支剧情树。场景是线性的，分支只在"玩家选择"处。
- 不做多结局动画。结局是文字，黑屏白字。

详见 `SCENARIO_ISPYTANIE.md`（六幕内容）、`SCEN_ENGINE.md`（引擎接入）。

## 15 终局体系

### 15.1 终局类型

| 终局 | 触发源 | 条件 | 评价 |
|------|--------|------|------|
| 爆炸 | SCENARIO_END | 场景终局事件（EXPLOSION） | 切尔诺贝利全貌 |
| 熔毁 | MELTDOWN | 堆芯熔毁 / 功率超量程 / 不可恢复事故 | 放射性泄漏 |
| 正常结束 | SCENARIO_END | 事件列表走完 / 安全停堆 | 正常收班 |
| 主动退班 | VOLUNTARY | 玩家 F12 或暂停菜单"结束值班" | 中断记录 |
| 挑战结算 | CHALLENGE_END | 倒计时归零 / 目标达成 | 得分排名 |

> 行政管理终局（撤职：信任归零，§9；破产：连续 6 个月净亏损，§8.3）属无尽模式远期功能，当前生命周期未定义触发源，接入时映射为 SCENARIO_END（事件触发）。

### 15.2 触发源优先级（PLAYING → ENDING）

| 优先级 | 触发源 | 条件 | 终局类型标记 |
|--------|--------|------|-------------|
| 1 | 物理引擎 | 燃料温度 > 2800°C / 热功率 > 32000 MW / 空泡份额 > 100% | MELTDOWN |
| 2 | 场景引擎 | 终局事件被消费 / 剧本条件命中 | SCENARIO_END |
| 3 | 玩家主动 | F12 或菜单内"退班"，需确认 | VOLUNTARY |
| 4 | 挑战模式 | 时间耗尽（TIMEOUT）/ 目标达成（OBJECTIVE_COMPLETE） | CHALLENGE_END |

MELTDOWN 不可覆盖，一旦触发不接受任何撤销。

### 15.3 终局流程

PLAYING → ENDING（过渡动画 1.5-3s，按终局类型区分）→ DEBRIEF（结算画面）→ MENU。

- 结算左栏 = 数据（时长、终局类型、最终功率、ORM、操作次数），右栏 = 评语/尾声
- 评分按 5 维（规程/安全/响应/设备/记录），历史模式附加历史匹配度，见 `SCORING.md`、`DEBRIEF.md`
- 结算写入值班日志（存档），见 §19、`SAVE.md`
- 生命周期状态机与模块接口详见 `FLOW.md`

## 16 难度设计

### 16.1 核心原则

难度不是"敌人更强"。难度是"给你的更少"。

没有血条，没有敌人，没有倒计时读条。难度的本质是：你和反应堆之间，隔了多少层信息。

### 16.2 难度维度

不是一个滑块。是五个独立轴。

| 轴 | 低难度 | 高难度 |
|----|--------|--------|
| 信息透明度 | 异常参数高亮闪烁，故障源直接标注 | 所有仪表一视同仁，你自己判断哪个不对 |
| 时间裕度 | 从异常到不可逆，5 分钟以上 | 90 秒 |
| 规程辅助 | 手册自动翻到相关页，步骤逐条提示 | 手册在那，自己找，自己读，没人等你 |
| 容错 | 错误操作有缓冲期，可以撤回 | 一步错，直接进事故工况 |
| 指令明确度 | 值班长说"把功率降到 50%" | 值班长说"上面不满意，你看着办" |

### 16.3 难度等级

难度不叫"简单/普通/困难"。叫值班等级。叙事内嵌。

| 等级 | 名称 | 叙事含义 | 对应玩家 |
|------|------|----------|----------|
| 1 | 实习操纵员 | 师傅在旁边，什么都告诉你 | 第一次玩 |
| 2 | 值班操纵员 | 独立值班，规程在手，时间够用 | 通关一次后 |
| 3 | 高级操纵员 | 没有提示，时间紧，指令模糊 | 追求挑战 |
| 4 | 事故工况 | 一切都在坏，信息互相矛盾，没有正确答案 | 自虐 |

不设"自定义难度"。五个轴绑定在等级里，不拆开给玩家调。原因：这游戏的核心体验是"在信息不足时做决定"。如果玩家把信息透明度拉满，游戏就不存在了。

设置屏中的"工况/难度"分区（数字辅助、故障预警等级、后果模式）不属于五个难度轴——它们只改变信息呈现方式，不改变操作后果。详见 `SETTINGS.md` §4.4。

### 16.4 各等级具体差异

**等级 1：实习操纵员**
- 异常仪表黄色闪烁 + 文字标注"注意：一回路温度偏高"
- 手册自动打开到对应章节，当前步骤加粗
- 值班长指令具体到操作："将第 12 组控制棒下插 30 厘米"
- 错误操作后 10 秒内可撤回（棒可以拉回来，阀门可以关回去）
- 从异常到不可逆：8 分钟
- 结算时额外显示"你本应该做什么"

**等级 2：值班操纵员**
- 异常仪表仅闪烁，无文字标注
- 手册不自动翻页，但目录有标记
- 值班长指令是目标："把一回路温度压回 280"
- 错误操作有 3 秒缓冲，之后锁定
- 从异常到不可逆：4 分钟
- 结算时显示标准评价

**等级 3：高级操纵员**
- 无闪烁。仪表就是仪表。你自己看。
- 手册无任何辅助。
- 值班长指令模糊："上面问你怎么回事，你给个说法"
- 无缓冲。操作即生效。
- 从异常到不可逆：2 分钟
- 结算时只显示结果，不解释

**等级 4：事故工况**
- 部分仪表给错误读数（传感器故障）
- 手册可能缺页（被撕了、被咖啡泡了）
- 值班长可能给错误指令（他也不知道发生了什么）
- 无缓冲。且存在"操作本身加剧事故"的可能
- 从异常到不可逆：60 秒
- 没有"正确答案"。结算时显示"你做了什么"和"发生了什么"，不评价对错

### 16.5 难度递进（跨场景）

不是"第一关简单第二关难"。是同一等级内，场景本身在变复杂。

| 阶段 | 特征 |
|------|------|
| 前期场景 | 单一故障。一个参数偏了。你调回来。完事。 |
| 中期场景 | 耦合故障。调了一个，另一个跟着动。你得想顺序。 |
| 后期场景 | 信息矛盾。两个仪表说的不一样。你得判断谁坏了。 |
| 终局场景 | 没有正确操作。你只能选"哪种死法"。 |

难度等级决定你获得多少帮助。场景进度决定问题本身有多复杂。两者独立。

一个等级 1 的玩家在后期场景里也会遇到信息矛盾——只是游戏会告诉他"这两个仪表矛盾了"。等级 3 的玩家在前期场景里也不会得到提示——只是问题本身简单，不需要提示也能过。

### 16.6 解锁规则

| 等级 | 解锁条件 |
|------|----------|
| 1 | 默认 |
| 2 | 以等级 1 完成全部场景 |
| 3 | 以等级 2 完成全部场景，且总评分 ≥ B |
| 4 | 以等级 3 完成全部场景 |

不跳级。原因：等级 3 和 4 要求玩家已经内化了规程。如果没经历过等级 1 和 2 的辅助阶段，玩家不是在"做困难决定"，是在"乱按"。

### 16.7 与其他系统的接口

| 系统 | 接口 |
|------|------|
| SCENARIO_ISPYTANIE.md | 剧本中标注 min_difficulty 字段。低于此等级的玩家不会遇到某些分支。 |
| SCORING.md | 等级 4 的结算使用不同的评价模板（不评对错，只记录）。 |
| UI_INTERACTION.md | 等级 1-2 的 UI 有额外高亮层。等级 3-4 移除。 |
| AUDIO_IMPL.md | 等级 1 有语音提示（"注意，一回路温度超限"）。等级 3 起只有报警声，没有语音。 |

### 16.8 不做的事

| 不做 | 原因 |
|-----|------|
| 辅助模式/无障碍模式 | 信息透明度已经是最低难度轴。再低就没有游戏了。 |
| 一命通关 | 这游戏本来就是一命。没有 checkpoint。事故就是事故。 |
| 动态难度调节 | 不根据玩家表现偷偷调参数。难度是透明的、固定的。 |
| 简单模式跳过某些场景 | 所有等级玩同样的场景。差异只在辅助程度。 |

## 19 存档系统

### 19.1 设计哲学

存档的 diegetic 形式：值班日志（Вахтенный журнал）。每个核电站都有。每次操作都记录在案。

- 存档是记录，不是状态快照。不存"游戏进行到哪里了"。存"发生了什么事"。
- 没有"自动存档"，只有"记录"（事件发生时自动写入，像真实日志）。
- 没有"存档槽位"，只有一本日志，按时间顺序排列。
- 没有 Continue 按钮。只有"开始新班次"。

### 19.2 存储

| 平台 | 位置 |
|------|------|
| Web | localStorage，键 `rbmk_journal` |
| LÖVE | love.filesystem.getSaveDirectory() / journal.json |

支持导出/导入（diegetic 理由："交接记录"）。

### 19.3 数据结构

顶层：`version, created, lastModified, operator, settings, entries, campaign, statistics`。

- `operator`：呼号、班次数、首末次值班时间
- `settings`：游戏设置（扁平结构，扩展见 `SETTINGS.md`）
- `entries`：所有值班记录（每次值班结束时追加一条，含 5 维评分、决策列表、历史匹配度）
- `campaign` / `statistics`：战役状态与累计统计

### 19.4 接口

```
Save.loadJournal() / saveJournal() / recordShiftEnd({...}) / export() / import()
```

键名统一为 `rbmk_journal`。详见 `SAVE.md`。

## 20 音频设计

### 19.1 约束

- 零外部音频文件。全部 Web Audio API 合成。
- 目标体积：0 KB 音频资源。
- 目标性能：≤ 20 个同时活跃节点，CPU < 5%。

### 19.2 总线架构

5 层总线树：`Ambient → Equipment → Events → Alarms → Narrative`，各层独立 gain 控制，带 ducking 逻辑（报警时降低其他层音量）。

### 19.3 声层

| 层 | 内容 | 技术 |
|----|------|------|
| 环境 | 50Hz 变压器嗡鸣、通风管道低噪、管道应力 | 振荡器 + 滤波器 |
| 设备 | 泵嗡鸣（转速同步）、继电器咔哒、阀门电机 | 脉冲 + 扫频 |
| 事件 | 按钮/开关/钥匙咔哒、纸页翻动、电话铃 | 短脉冲合成 |
| 报警 | П1-П5 保护信号、AZ-5 动作、通用警铃 | 方波/锯齿波振荡 + 闪烁 |
| 叙事 | 电话对话声、打印机电报声、盖革计数器 | 噪声 + 脉冲 |

### 19.4 动态调整

- 盖革计数器：频率随剂量率线性增加（剂量率 × 4 clicks/s）
- AZ-5 报警：方波 2kHz + 闪烁，持续直到确认
- 泵声：随转速/流量变化音调
- 暂停/降速时音调不变，事件更密集

详见 `dev/AUDIO_IMPL.md`。

修改版本号应当由sx1922本人决定，禁止私自修改版本号

### 21.3 语义版本规则

- **major**：大版本，游戏发生质变（正式发布、引擎重写）
- **minor**：中版本，新增可感知的功能模块
- **patch**：小版本，修 bug、调数值、改文案
- minor +1 → patch 归零；major +1 → minor 和 patch 均归零
- major = 0 表示开发阶段，major = 1 表示正式发布

### 21.4 修订代号规则

- 修 bug / 调参数（patch +1）：修订代号不变
- 新增功能模块（minor +1）：NN +1
- 新增机组场景（新 YY）：YY 更换，NN 重置为 01
- 重大重做（major +1）：全部重置

## 各系统设计意图

| 系统 | 意图 |
|------|------|
| 中子动力学 | 让玩家感受反应堆对操作的响应延迟和非线性 |
| 热工水力 | 让空泡系数成为核心风险 |
| 氙毒 | 强制玩家规划功率变化，不能随意启停 |
| 汽轮机 | 让发电效率与反应堆功率解耦 |
| 经济/政治 | 制造"安全生产 vs 完成指标"的核心矛盾 |
| 人员 | 让玩家不能只关注反应堆，还要关心操作员状态 |
| 安全试验任务链 | 让历史事件以可交互的方式呈现 |
