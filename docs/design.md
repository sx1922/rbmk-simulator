# RBMK-1000 模拟器 — 设定文档

## 游戏定位

第一人称核电站操作模拟。玩家扮演切尔诺贝利核电站第四机组的站长，在 1986 年 4 月的背景下，负责反应堆的日常运行、安全管理，并最终面临是否进行安全试验的选择。

## 核心体验

- **真实的物理模拟**：中子动力学、氙毒、空泡系数、温度反馈、AZ-5 瞬态
- **运营压力**：发电指标、设备维护、人员管理、上级信任
- **决策后果**：每一个操作都有物理和经济上的连锁反应
- **历史再现**：可完整经历切尔诺贝利事故的决策链

## 玩家体验流程

1. 启动游戏 → 选择难度
2. 熟悉仪表盘和操作面板
3. 启动反应堆 → 提升功率
4. 日常运营：调棒、调泵、维护、换料
5. 应对随机事件和设备故障
6. 触发安全试验任务链
7. 在决策点做出选择
8. 多种结局：正常运营、事故、经济崩溃、政治撤职

## 核心循环

```
玩家操作 → 修改 STATE → 物理步进 → 更新显示 → 等待下个操作
```

每 0.5 秒步进一次物理（对应游戏内约 15 分钟），玩家可随时介入。

## 设计原则

1. **物理先行**：所有游戏机制建立在物理模拟之上
2. **操作即后果**：无"正确"操作，只有权衡
3. **信息不完美**：仪表有误差、延迟、故障
4. **压力渐进**：难度不是通过数值堆叠，而是通过多种压力源叠加

## 红线

- 不美化核事故
- 不简化操作过程
- 不回避辐射后果

## 世界观

1986 年 4 月，切尔诺贝利核电站，列宁核电站第四机组。RBMK-1000 型反应堆，正空泡系数，石墨慢化，沸水冷却。

## 各系统设计意图

| 系统 | 意图 |
|------|------|
| 中子动力学 | 让玩家感受反应堆对操作的响应延迟和非线性 |
| 热工水力 | 让空泡系数成为核心风险 |
| 氙毒 | 强制玩家规划功率变化，不能随意启停 |
| 汽轮机 | 让发电效率与反应堆功率解耦 |
| 经济/政治 | 制造"安全生产 vs 完成指标"的核心矛盾 |
| 人员 | 让玩家不能只关注反应堆，还要关心操作员状态 |
| 安全试验任务链 | 让历史事件以可交互的方式呈现 |

## 难度/终局设计意图

- 简单难度：容错高，设备可靠，适合学习
- 普通难度：平衡体验
- 困难难度：设备频繁故障，政治压力大

终局不是"失败"，而是各种压力源叠加导致的失控。

## 情绪曲线

1. 平静期：学习操作，熟悉系统
2. 紧张期：处理事件，应对故障
3. 危机期：安全试验决策，事故应对
4. 结局期：承受后果，评价总结

## 版本号系统（项目「ЩИТ」通用）

版本号采用三层结构，兼顾技术管理、时间追溯和游戏世界观表达。

### 完整格式

```
v{major}.{minor}.{patch} · сб.{YYYY.MM.DD} · РЭ-{YY}/{NN}
```

示例：`v0.1.0 · сб.2026.07.30 · РЭ-86/12`

### 三层职责

| 层 | 格式 | 职责 |
|----|------|------|
| 语义版本 | v{major}.{minor}.{patch} | 技术层，管"改了什么" |
| 构建日期 | сб.{YYYY.MM.DD} | 时间层，管"什么时候" |
| 修订代号 | РЭ-{YY}/{NN} | 叙事层，管"游戏里的身份" |

### 语义版本规则

- **major**：大版本，游戏发生质变（正式发布、引擎重写）
- **minor**：中版本，新增可感知的功能模块
- **patch**：小版本，修 bug、调数值、改文案
- minor +1 → patch 归零；major +1 → minor 和 patch 均归零
- major = 0 表示开发阶段，major = 1 表示正式发布

功能模块定义（每项算一个 minor）：
控制室面板系统、主菜单与场景框架、历史重演剧本、结算报告系统、音效系统、挑战模式、存档系统、新增机组场景

### 修订代号规则

- 修 bug / 调参数（patch +1）：修订代号不变
- 新增功能模块（minor +1）：NN +1
- 新增机组场景（新 YY）：YY 更换，NN 重置为 01
- 重大重做（major +1）：全部重置
- 代号与游戏内手册的"修改通知"页面联动

### 单一来源

项目根目录 `version.json` 作为唯一版本来源，所有 UI 从此文件读取，不硬编码。

### 跨平台同步

Web 和 LÖVE 使用相同版本号，通过平台标识区分。构建日期各自独立。

## Web 版本架构 (`rbmk-sim/`)

### 文件结构

```
rbmk-sim/
├── version.json        # 版本信息（单一来源）
├── index.html          # 入口，加载所有 JS 模块
├── style.css           # 苏联控制室主题（1200+ 行）
└── js/
    ├── engine.js       # 物理引擎（点堆动力学、空泡、氙、棒、保护、熔毁）
    ├── render.js       # Canvas 渲染（表盘、堆芯剖面、棒位、反应性、图表、时钟）
    ├── props.js        # 桌面道具（手册、剪贴板、计算器、剂量计、电话、茶炊）
    └── app.js          # 主循环 + UI 绑定（滑块、摇杆、泵、AZ-5、日志、报警灯）
```

### 技术选型

| 项 | 选择 |
|----|------|
| 渲染 | DOM + Canvas 2D |
| 音效 | Web Audio API（规划中） |
| 存档 | localStorage（规划中） |
| 字体 | Google Fonts (PT Sans, PT Mono, Oswald, Marck Script) |
| 依赖 | 无 |

### 设计特点

- 纯前端，无后端依赖
- 所有模块通过 IIFE 隔离，全局命名空间为 `RBMK`、`Render`、`Props`
- Unicode 转义处理 CJK/Cyrillic 字符串，避免编码问题
